- `MAX_MEMORY_CHARS` 40000 (was 32000), `MIN_MEMORY_CHARS` 4000, limit 200000, configurable via `maxMemoryChars`. It is the single source of that default — `DEFAULT_CONFIG.maxMemoryChars` and every fallback `limit` parameter read it — so raising the config field alone would leave two different “defaults” and let a call site that omits the limit clip silently. Every `normalizeMemoryDocument` call site takes the limit — read the call-site count fresh.
- A capped document is cut on a line boundary (`clipToLineBoundary`, never a bare slice) and carries the marker `_[memory truncated at <limit> characters: <dropped> dropped]_`; `isMemoryTruncated(text)` and `clipToLineBoundary` live in `src/project-memory/document.ts` and take the document string, not the `LoadedMemory` object; `loadMemory(projectRoot, limit)` is async and returns `{text, source, poisoned, unreadable?, damaged?}`.
- Editing MEMORY.md with the edit tool bypasses the plugin write path, and the next plugin write silently drops the excess: check with `wc -m` (characters; `wc -c` is bytes and overstates CJK by about a third) plus `loadMemory(root, MAX_MEMORY_CHARS)` plus `isMemoryTruncated(loaded.text) === false`, never by grepping for the marker.

A refused reply's losses are reported separately in `refusedLoss` and never mixed into the landed counts.

## Pitfalls
- Memory loss in a consolidation pass happens before or at the write, so a stored document that re-renders clean proves nothing. The five reachable sites are `fitMemoryInput` head-and-tail clipping, `renderMemoryDocument` dropping whole entries over a section budget, the stored context sliced to `MAX_CONTEXT_CHARS` before the fit, `renderContextDocument` clipping its own sections, and `normalizeMemoryDocument` capping on write. `ConsolidateReport` carries the six loss counts plus `memoryWritten`/`contextWritten`, zeroed unless that artifact landed; every lossy write logs a line.
- Gate numbers written down always expire: run `pnpm typecheck` / `pnpm build` / `pnpm test` and read pass and case counts, take `lib/client.js` size from build output, and expect 0 mutant markers in `lib/`. Historical mutation rounds are not enumerated.
- The loaded-memory trap: `loadMemory` can return a document that already carries the truncation marker while the status object still reports `damaged: 0` and `poisoned: false`, so the status view shows a healthy document whose tail is gone. The marker's `dropped` is normalized length minus kept prefix length, not original minus kept, because normalization strips the header, code fences and old markers and trims — never verify it by arithmetic and never grep for the marker.
- `tsc` emits tagged templates as `String.raw` followed by the template with a space, so `grep -cF` for an in-template marker returns 0 and looks like a failed restore or an empty mutant; locate mutants with `grep -n "<NAME> = "` in `lib/`.
- String counts taken from session logs are unusable because logs echo the agent's own command output, so `grep -c` mostly counts the probe itself; judge live behaviour through read-only interfaces (`cordis_inspect_query` `Config`/`Service`, projection caches) instead.
- `/handoff status` receipts do not self-identify: `threshold auto` and `context` are profile- and model-level numbers identical across workspaces, so any citation must carry workspace plus session id — this was once misread as this project's session's receipt when it belonged to another workspace.
- An invalid mutant's red is not evidence — leaving a symbol unreferenced in `src/` makes `tsc` report `TS6133`, so keep every symbol referenced before judging red.
- Cross-repo transfer trap: dsh's finish reason is `max-tokens` while pi's is `length`, and copying pi's string silently disables the retry path.
- The harness's subagent-list `activity` field means resident, not working: `list-children.ts` builds `childRow(…, 'running', …)` for every candidate `sessions.get(id)` still holds and only a cold read gives `'inactive'` — never read a listing's `activity` as working now; use upstream's `list_agents`, which re-derives from the live registry.
- `subagents.listChildren(parentId)` returns direct children from the parent-owned `subagent/catalog` projection; the row shape differs by version (0.1.6 `SubagentListEntry` carries `activity`/`hasChildren`, 0.1.7-alpha.1+ `SubagentCatalogEntry`), both carry `mode`, and teammates are in this catalog, so one read covers both.
- Auto handoff is evaluated only on `turn/end` and has no timer (`src/project-handoff/index.ts`'s `session/event` filter returns for everything else), so a session far past the threshold that never ends a turn never hands off. The second gate is `handoffPendingQuestion`, right after the threshold, on whether the last assistant message ends in a question.
- Do not diagnose out of order: both pre-checks (pending question, running subagent) sort after the threshold, `/handoff now` checks neither gate, and `/handoff threshold 0.4` does not clear the knee. Judge live verification across all workspaces, not only the one asked about — before the auto-path fix the path was structurally untriggerable, so one trigger proved the fix loaded.
- A third-party plugin can break desktop boot, so a plugin's restart failure is not automatically your change not taking effect: the desktop host's `~/.config/@deepseek-ai/dsh-desktop/logs/crash-*-host.log` records `dsh: skipping profile bundle "<plugin>"` plus a `peerDependencies` incompatibility line, then the host stops — the real cause is a peer line differing from the running dsh. Read `dsh --version` fresh instead of hardcoding it, and attribute files by mtime first: an old instance's logs get misread as a live fault.
- `dsh-rewind-plugin` is fully disposed and that closure is verified empirically, not structurally: `/etc/nixos` no longer declares it, both profiles are clean, and the HM `programs.dsh.plugins` module only writes ensure-missing commands for declared entries and never deletes — prove 0 hits with `grep -c rewind $(readlink -f ~/.local/state/home-manager/gcroots/current-home)/activate` while that file still carries the other entries' commands.
- A memory doc whose mtime is fresh while `git status --short` is clean is normally the last commit's own write, not a concurrent writer — compare that mtime against the commit time of the last commit touching the file before concluding, read the files inside a session directory rather than the directory mtime (it only moves on create/delete), and prove idleness with an mtime window plus `git status --short` reporting 0 changes.
- Profile-layer `cordis.patch.yml` mtime moving forward means the platform is persisting settings, not that someone edited config: the settings pages write through `settings.mutate` (each write carries a `revision`, and concurrent external edits are rejected as `settings/conflict`). Manual agent edits leave `.bak-<date>-<purpose>` files, programmatic writes leave none, and mtime moves even without new content.
- `test/card-render.test.mjs` must supply `react-dom` / `clsx` / `zustand` / `immer` itself, because the client packages import them while declaring only a cordis peer, plus passthroughs for `ui-primitives`' mega-index (shiki/katex/micromark/simple-icons). The migrated card runs through one platform require in `lib/client.js` and none in the deleted hand-written card, and a frame's file size is not a page classifier.
- The `本会话 ¥…` line is third-party `dsh-cost-meter`'s cell in the session-scoped `conversation.composer.dock` slot (one per mounted conversation), not this repo's render; cross-check read-only via host `Config` for `name=dsh-cost-meter`, client `Slots` on that root, or `~/.dsh/storages/cost-meter/ledger.json` → `days.<date>.sessions[]`. Two lines under ONE composer mean a stale client registration (Ctrl+Shift+R); two composers each with a live line mean two sessions. The ledger bills per call; `includeSubagentCost` merges only continuous subagent descendants — neither is a defect.
- A verification script must prove its own tool surface and every failure path must be reachable: under `set -euo pipefail`, `x="$(grep … | head -1 | sed …)"` makes the script exit before its own fail branch when the grep misses — for every `var="$(…)"` ask whether the next branch that reads it is still reachable.
- Cross-metric subtraction once left auto mode structurally thresholdless (found 2026-09-27, fixed 2026-10-02): the old `floor` mixed a provider-anchored `totalTokens` with a `CHARS_PER_TOKEN = 4` heuristic for `surfaceTokens`, so the difference carried density error and grew with CJK count — see the `floor` invariant.
- Never rewrite a long line with a prefix-relative replace: the remainder survives and the line ends in a duplicated remnant. Read the line back and check that the same sentence does not appear twice.
- Cross-checking `.agents/memory/session-logs/INDEX.md` against the disk must parse each bullet's link target, never an id anywhere in the line: a session title can quote another session's id, so an anywhere-in-line match reports a false dangling entry (and hides the real count) while a link-target match gives 78 bullets ↔ 78 directories, 0 dangling, 0 unindexed.
- A config-key rename here is a breaking change with **no compatibility reader** (batch H, 2026-10-05): our values live in each profile's `cordis.patch.yml`, which this repo cannot rewrite, so an alias could never retire. A retired name is an *unknown* key, and the failure is only **half loud**: the `project-context` entry (the settings-namespace owner) throws at apply and loses its card, while the other three entries carry no config of their own and fall back to `DEFAULT_CONFIG` **silently**. So edit both profiles **first**, then restart. Six faces move together: `config.ts`, `settings.ts`, `client/card-fields.ts`, `locales.ts`'s `field.*` keys, every reader and `settingPatch` write-back key, and tests.
- A render round-trip, not `isMemoryTruncated`, proves a hand-edited MEMORY.md is safe: the document cap can read `truncated:false` while one entry over `MAX_LIST_ITEM_CHARS` (800) is already queued for a silent clip. Check with `sectionsFromMarkdown` → `renderMemoryDocument`: `itemTruncated 0` and a byte-identical round trip; split the long entry rather than dropping the fact.
- Batches G and H (pi pass `f6bea1d..ca71fd3`, landed 2026-10-05): a learned body is pulled only when the model asks with `inspect_skill`, and a marked name whose body that round did not render is refused with `body not shown this pass` at the gate and independently at the write path; H carried all seven key renames with no reader plus the memory-layer `Memory: ` prefix. Briefs and rulings: `docs/batch-{g,h}-*.md`, `docs/vocabulary-conventions.md`.

- docs/ and CHANGELOG.md 未发布 carry the pi triage, port batches and per-item port mappings; the pi triage index and each batch's rationale live there rather than in memory.
- src/project-context/index.ts holds the archive write gates; src/shared/config.ts and client/locales.ts hold the config keys and the client hint strings.
- src/project-memory/{consolidate.ts,sections.ts,memory-schema.ts,document.ts,load.ts} hold memory reading, rendering, capping and tier C; src/project-autolearn/{pass,schema,skill,candidate,inventory,prompt}.ts hold the autolearn pass and the supersede marker; src/project-handoff/{auto,perform,threshold,command}.ts hold handoff decisions, receipts and the command surface.
- test/ contains logic.test.mjs plus the gate, render, settings and client-injection suites; .agents/evidence/ holds the per-round probes and mutation records that back the code comments.
- The delivery line's authoritative copies live in /etc/nixos (`scripts/dsh-plugin-patches/PINNING-RISK.md` and `log.md`, found by entry header rather than by number), and this repo keeps only a pointer plus the `dsh-nix-desktop-launcher-artifact-verify` skill; `/etc/nixos/scripts/dsh-desktop-restart.sh` is user-run with `--dry-run` / `--verify-only` available in-session.
- `/mnt/Data/Backups/dsh-project-context/purge-subagent-archives.mjs` purges archives of delegated children: it classifies each archive by its `session` header, refuses if a child id is referenced by a tracked file, tars the children outside the repo, deletes them, and rewrites INDEX.md through the plugin's lock — it is idempotent and a no-op when no child archives exist, so it only needs re-running after a restart that loaded pre-`isTopLevel` code.
- Commands: `git rev-parse HEAD origin/main`; `git ls-remote 'refs/tags/<tag>*'` (gives the tag object and its peeled commit, so a push can be verified without a full fetch); `ss -ltnp | grep 19387` then `ps -o lstart= -p <pid>`; `loadMemory(root, MAX_MEMORY_CHARS)` plus `isMemoryTruncated(loaded.text)`; `ls -d .agents/skills/*/` against `git ls-files '.agents/skills/**/SKILL.md'`.
- pi is at `/mnt/Data/Projects/pi-project-context`, a separate checkout with its own release and test conventions; dsh runtime and profile facts belong to this repo's docs, not to that tree.
