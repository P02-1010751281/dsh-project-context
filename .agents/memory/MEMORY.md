## Pitfalls
- Memory loss happens before or at the write, so a clean re-render proves nothing; the five sites are `fitMemoryInput` head-and-tail clipping, `renderMemoryDocument` dropping entries over a section budget, the stored context sliced to `MAX_CONTEXT_CHARS` before the fit, `renderContextDocument` clipping its sections, and `normalizeMemoryDocument` capping on write; `ConsolidateReport` carries the six loss counts plus `memoryWritten`/`contextWritten`.（bbc）
- `/memory update` refuses for two unrelated reasons — section budgets (`lossy-refused`: `N section(s) exceeded their budget` or `N whole entry(ies) … reached its character cap`) and the model output cap (`cut off by the model output limit`); raising `maxMemoryChars` only aggravates the output half, the durable fix is shrinking the document; `fit-capped-refused` means the output budget cannot hold both documents.（d54）
- Gate numbers and occupancy prose expire: run `pnpm typecheck` / `pnpm build` / `pnpm test` and read fresh counts, take `lib/client.js` size from the build output, expect 0 mutant markers, and re-measure per-section occupancy through the built renderer (`share-fit.mjs`) rather than trusting written percentages.（846）
- `share-fit.mjs` measures against the library default `MAX_MEMORY_CHARS`, not the profile's `maxMemoryChars`, so it can report a lossy verdict the running host would never produce; compare against the configured cap before believing it.（a4d）
- The loaded-memory trap: `loadMemory` can return a document that already carries the truncation marker while the status object still reports `damaged: 0` and `poisoned: false`; the marker's `dropped` is normalized length minus kept prefix length, not original minus kept — never verify it by arithmetic and never grep for the marker.（1a8）
- `tsc` emits tagged templates as `String.raw` followed by the template with a space, so `grep -cF` for an in-template marker returns 0 and looks like a failed restore or an empty mutant; locate mutants with `grep -n "<NAME> = "` in `lib/`.（4a7）
- String counts taken from session logs are unusable because logs echo the agent's own command output, so `grep -c` mostly counts the probe itself; judge live behaviour through read-only interfaces (`cordis_inspect_query` `Config`/`Service`, projection caches).（17e）
- Do not filter a multi-line log by string-comparing whole lines against a timestamp: continuation lines of a stack trace start with `{` or whitespace and sort after `2026…`, so they read as newer entries and hide the one real error — match a line-leading timestamp instead.（34b）
- A restart-time `[handoff] LlmError: … has no configured model …` is that stale header pair (see the handoff route invariant), not a code defect: `withRouteFailure` wraps the `HandoffRouteError` onto the `handoff-pressure` line, `/handoff status` names the pair, and the catch logs and backs off 5 minutes.（a5f）
- A profile whose installed code predates a new config key fails at apply rather than warning: the entry stays enabled but not active (the `--verify-only` table loses `include:project-context`) because the old parser rejects `handoffThreshold` as an unknown key; raise that profile's pin or tgz and restart instead of editing config.（02f）
- `[memory] … cannot get required service "llm" in inactive context` lines a second or two before a host start are the old instance's dispose-time cleanup, not a new defect (cluster at every shutdown); likewise a cap-loss line dated just before a restart was written by the old code under the old cap.（96d）
- `/handoff status` receipts do not self-identify: `threshold auto` and `context` are profile- and model-level numbers identical across workspaces, so any citation must carry workspace plus session id.（935）
- An invalid mutant's red is not evidence — leaving a symbol unreferenced in `src/` makes `tsc` report `TS6133`, so keep every symbol referenced before judging red.（8db）
- Cross-repo transfer trap: dsh's finish reason is `max-tokens` while pi's is `length`, and copying pi's string silently disables the retry path.（dcc）
- pi batch I (loaded): the injected documents keep the policy sections inline and index the rest; an unnamed heading and a trailing `_[…]_` note stay inline, pointers are absolute, and the pointer language follows the document's own detector (`src/shared/language.ts`).（b16）
- pi batch J (loaded): the handoff summarizer is gone and `handoffThinking`/`/handoff thinking` retired hard-cut, so `/handoff now` needs no routed model while the auto path still resolves `contextWindow`; `isHandoffContinuationText` stays structural — a payload change must keep all six `<handoff>` closings matching or a seed counts as a human turn.（ac9）
- The harness's subagent-list `activity` field means resident, not working: `list-children.ts` builds `childRow(…, 'running', …)` for every candidate `sessions.get(id)` still holds and only a cold read gives `inactive`, so judge live work with upstream's `list_agents`; `subagents.listChildren(parentId)` reads the parent-owned `subagent/catalog` projection instead.（071）
- Auto handoff is evaluated only on `turn/end` and has no timer, so a session far past the threshold that never ends a turn never hands off; the second gate is `handoffPendingQuestion`, right after the threshold, and only `defer` blocks.（f70）
- Crossing the threshold is necessary but not sufficient: the decision also skips with `nothing-to-drop` when the recent-token window already covers the whole session, so a threshold breach alone never predicts a handoff.（af4）
- Do not diagnose out of order: both pre-checks (pending question, running subagent) sort after the threshold, `/handoff now` checks neither gate, and `/handoff threshold 0.4` does not clear the knee; judge live verification across all workspaces, not only the one asked about.（a49）
- A third-party plugin can break desktop boot, so a restart failure need not be your change: `~/.config/@deepseek-ai/dsh-desktop/logs/crash-*-host.log` records `dsh: skipping profile bundle` plus a `peerDependencies` incompatibility line, then the host stops; read `dsh --version` fresh, attribute files by mtime.（f54）
- `dsh-rewind-plugin` is fully disposed (`/etc/nixos` no longer declares it, both profiles are clean, the HM module only writes ensure-missing commands); prove 0 hits with `grep -c rewind` on the current-home activate script.（7b6）
- A memory doc whose mtime is fresh while `git status --short` is clean is normally the last commit's own write — compare that mtime against the commit time of the last commit touching the file, read files inside a session directory rather than the directory mtime, and remember `wc -m` counts characters while `ls -l` counts bytes.（548）
- A forward `cordis.patch.yml` mtime means the platform is persisting settings, not someone editing config: settings pages write through `settings.mutate` with a `revision`, concurrent external edits rejected as `settings/conflict`; agent edits leave `.bak-<date>-<purpose>` files and line numbers drift — grep the key, never cite a line anchor.（3d7）
- `test/card-render.test.mjs` must supply `react-dom` / `clsx` / `zustand` / `immer` itself (the client packages import them while declaring only a cordis peer) plus passthroughs for `ui-primitives`' mega-index (shiki/katex/micromark/simple-icons); the migrated card runs through one platform require in `lib/client.js`.（9f7）
- The `本会话 ¥…` line is third-party `dsh-cost-meter`'s cell in the session-scoped `conversation.composer.dock` slot; cross-check read-only via host `Config` (`name=dsh-cost-meter`), client `Slots` on that root, or `~/.dsh/storages/cost-meter/ledger.json` → `days.<date>.sessions[]`; two lines under ONE composer mean a stale client registration.（3c1）
- A verification script must prove its own tool surface and every failure path must be reachable: under `set -euo pipefail`, `x="$(grep … | head -1 | sed …)"` exits before its fail branch when the grep misses; a probe feeding an already-rendered document into the renderer reports `sectionDropped 0`, so exercise the budget branch with a constructed over-cap string, and read `MemorySections` by lowercase keys.（a0f）
- Never rewrite a long line with a prefix-relative replace: the remainder survives and the line ends in a duplicated remnant; read the line back and check that the same sentence does not appear twice.（af3）
- Cross-checking `.agents/memory/session-logs/INDEX.md` against the disk must parse each bullet's link target, never an id anywhere in the line (a session title can quote another session's id), and never count directories with a `session-*` glob, which undercounts.（51e）
- A config-key rename is breaking with no compatibility reader (batch H): our values live in each profile's `cordis.patch.yml`, which this repo cannot rewrite, so an alias could never retire; the failure is half loud — the `project-context` entry throws at apply and loses its card while the other three silently fall back to `DEFAULT_CONFIG`. Edit both profiles first, then restart, moving six faces: `config.ts`, `settings.ts`, `client/card-fields.ts`, `locales.ts`'s `field.*`, every reader and `settingPatch` write-back key, and tests.（0da）
- A render round-trip, not `isMemoryTruncated`, proves a hand-edited document safe: the cap can read `truncated:false` while an entry over `MAX_LIST_ITEM_CHARS` (800) is queued for a silent clip; `CONTEXT.md` and `MEMORY.md` each need it (`roundtrip.mjs` / `share-fit.mjs`) — `itemTruncated 0`, no entry at the cap, byte-identical round trip, and split the long entry rather than dropping the fact.（b96）
- A context document can starve its own tail (Open tasks once sat at 99.7% of its share, so the next pass would have dropped trailing entries), so measure per-section occupancy after any large hand edit, write one `- ` bullet per statement instead of appending plain text (which splices into the last bullet and swallows the heading), and supply `options.updatedAt` when calling `renderContextDocument` directly.（33f）
- A refusal's input document version cannot be proven after the fact — the request body is not persisted, the cost ledger aggregates per session, and the host writes no `[memory]` runtime log — so attribute it by `MEMORY.md`'s mtime plus the rule that a refusal after the next restart is unambiguous; any written claim that a batch is live decays and must be re-derived from the timestamp criterion and the probe.（0cf）
- A restart verification script can print `RESULT: FAIL` for a reason unrelated to this repo: `/etc/nixos/scripts/dsh-desktop-restart.sh --verify-only` fails while a second unrelated desktop is alive, and an acceptance script's own `title-load verify` half fails until its criterion is re-run after the restart.（005）
- `dsh-live-inventory-probe.mjs`'s `--expect` takes plugin `moduleName` suffixes, not package names: our four rows are `dsh-project-context`, `dsh-project-context/memory`, `dsh-project-context/autolearn`, `dsh-project-context/handoff`, so passing `dsh-project-memory` yields a false `NOT FOUND` / FAIL against a perfectly loaded host.（cf5）
- A learned body is pulled only when the model asks with `inspect_skill`, and a marked name whose body that round did not render is refused with `body not shown this pass` at the gate and at the write path; briefs live in `docs/archive/batch-{g,h}-*.md` and `docs/vocabulary-conventions.md`.（6f4）
- dsh ships machine-readable upgrade guides under `docs/upgrade-guide/` in the store repo — read them per version before reasoning about a delta, but a guide describes declared intent, so confirm the behaviour in the shipped `lib/`; a stale config key that dsh's schemastery no longer declares is accepted silently and does nothing.（367）
- A probe that matches a rendered section heading must use the bare `MEMORY_SECTIONS` / `CONTEXT_SECTIONS` name: the specs carry no `## `, so matching the rendered string under-reports occupancy by orders of magnitude.（3db）
- A green suite does not mean the live config branch is covered: batch W's mutation F deleted the `handoffPendingQuestion === "defer"` guard and nothing went red until a case was added, because both profiles write `wait` — the only branch production reads was untested.（3b5）
- A green acceptance probe plus no new failure signature does not prove a model-call fix: after a restart check the router log for an auxiliary call issued by the plugin path, since main-turn traffic carries `tools: []` too.（ba9）
- A first pass at judging anchors is too wide if it counts bare file names (`session.md`, `CONTEXT.md`) as paths: only directory-qualified paths and line anchors are checkable drift.（bf8）
- `session-index.ts`'s `entryLines` keeps only `- [` lines and `LINE_PATTERN` folds any extra in-line field into the title without erroring; after Z1 both serve only the adoption read, never the write path.（5fe）
- When a grilling round's answers contradict each other (retire-on-delete plus a 90-day buffer), resolve the contradiction with the user before writing the spec; it is cheaper to fix in conversation than in code.（f9a）
- Batch Z8d: `removedSectionEntries` compares entries only after `stripEntryTid`, since the plan can be stamped and the write-back not; verbatim that reported 107 deletions where 96 were unchanged. Pinned by `batch Z8d` in `test/logic.test.mjs`.（bde）
- `retireSections` builds its id map over all four sections and runs anchor drift plus the 180-day/unconfirmed rules on each, so a Project or Index entry can be retired as unconfirmed and a tight budget prunes their age data, pausing aging; the Invariants → Pitfalls → Project → Index stamping order is justified only by Project/Index being rewritten every pass, not by retirement reading identity from two sections.（bd7）
- Wording-only compression of `MEMORY.md` (mechanical per-line replacements that must keep every backticked token and number) buys only a few hundred characters once the document is dense; reclaiming more means deleting delivered batch bullets or whole facts, which is the user's call, so check headroom and ask before cutting content.（7c1）
