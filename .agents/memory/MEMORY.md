Read the version fresh with `grep '"version"' package.json` and `git tag -l --sort=-v:refname | head -1`; there are no GitHub Releases. A release is an annotated tag and changes no code, so it needs no desktop restart; the flow is the tracked skill `dsh-project-context-release`, and a released section gets dated addenda rather than rewrites.

## Invariants

Do not copy its numbers into memory. Each section has a hard budget and the renderer drops whole entries that overflow one, so keep every section comfortably inside its share.

- The empty-skeleton gate was a real blocker: its two halves judged different documents, so a `record_memory` call carrying only headings could replace the stored MEMORY.md with a skeleton and log nothing. Both halves now judge the rendered document through `replyIsSemanticallyEmpty`.
- Truncation guard semantics: a tool call is untrustworthy when the finish is `max-tokens` or empty (no terminal stream event), and both cases retry.

## Pitfalls
- Memory loss in a consolidation pass happens before the write, so a stored document that re-renders clean proves nothing: `fitMemoryInput` clips the stored memory head-and-tail when memory plus context exceed the model's output cap (logged as `shortened ... to fit the model output budget`, and a truncation retry adds 4096 tokens of headroom so it clips sooner), and `renderMemoryDocument` drops whole entries that overflow one section's budget (logged with the section and entry counts).
- Gate numbers written down always expire: run `pnpm typecheck` / `pnpm build` / `pnpm test` and read pass and case counts, take `lib/client.js` size from build output, and expect 0 mutant markers in `lib/`. Historical mutation rounds are not enumerated.
- The loaded-memory trap: `loadMemory` returns a document that already carries the truncation marker while the status object still reports `damaged: 0` and `poisoned: false`, so the status view shows a healthy document whose tail is already gone. The marker's `dropped` equals normalized length minus kept prefix length, not original length minus kept length, because normalization strips the header, code fences and old markers and trims — never verify it by subtracting two numbers, never quote concrete values, and never grep for the marker.
- `tsc` emits tagged templates as `String.raw` followed by the template with a space, so `grep -cF` for an in-template marker returns 0 and looks like a failed restore or an empty mutant; locate mutants with `grep -n "<NAME> = "` in `lib/`.
- String counts taken from session logs are unusable because logs echo the agent's own command output, so `grep -c` mostly counts the probe itself; judge live behaviour through read-only interfaces (`cordis_inspect_query` `Config`/`Service`, projection caches) instead.
- `/handoff status` receipts do not self-identify: `threshold auto` and `context` are profile- and model-level numbers that are identical across workspaces, so any citation must carry workspace plus session id. This has already been misread once as this project's session's receipt when it belonged to another workspace.
- Cross-metric subtraction once left auto mode structurally thresholdless (found 2026-09-27, fixed 2026-10-02): the old `floor` was `max(0, totalTokens − surfaceTokens) + keep + MIN_SUMMARIZE_TOKENS`, but the meter anchors `totalTokens` on provider `usage` while `surfaceTokens` is a fixed-density heuristic (`CHARS_PER_TOKEN = 4`), so the difference mixed real overhead with density error and grew with CJK character count.
- An invalid mutant's red is not evidence — leaving a symbol unreferenced in `src/` makes `tsc` report `TS6133`, so keep every symbol referenced before judging red.
- Cross-repo transfer trap: dsh's finish reason is `max-tokens` while pi's is `length`, and copying pi's string silently disables the retry path.
- The harness's subagent-list `activity` field means resident, not working: `list-children.ts` constructs `childRow(…, 'running', …)` for every candidate `sessions.get(id)` still holds and only a cold read gives `'inactive'`, while upstream's own `list_agents` re-derives from the live registry — never read a listing's `activity` as working now.
- `subagents.listChildren(parentId)` returns direct children from the parent-owned `subagent/catalog` projection: `SubagentListEntry` (`{kind, id, mode, activity, hasChildren}`) in 0.1.6 and `SubagentCatalogEntry` (`{id, createdAt, mode, label}`) from 0.1.7-alpha.1 on, both carrying `mode`, so one read covers both versions; teammates are in this catalog.
- Auto handoff is evaluated only on `turn/end` and has no timer (`src/project-handoff/index.ts`'s `session/event` filter returns for everything else), so a session far past the threshold that never ends a turn never hands off. The second gate is `handoffPendingQuestion`, evaluated right after the threshold on whether the last assistant message ends in a question.
- Do not diagnose out of order: both pre-checks (pending question, running subagent) sort after the threshold, `/handoff now` checks neither gate, and `/handoff 0.4` does not clear the knee. To judge live verification, scan all workspaces rather than only the one asked about — before the auto-path fix the path was structurally untriggerable, so one trigger was itself evidence the fix was loaded.
- A third-party plugin can break desktop boot, so do not read a plugin's restart failure as your change not taking effect: `~/.config/@deepseek-ai/dsh-desktop/logs/crash-*-host.log` records `dsh: skipping profile bundle "<plugin>"` plus a `peerDependencies` incompatibility line and then the host stops — the real cause is a plugin declaring a different peer line than the running dsh line. Read `dsh --version` fresh instead of hardcoding versions, and attribute files by mtime before reading that directory, since an old instance's logs get misread as a live fault.
- `dsh-rewind-plugin` is where a declarative manifest and manual cleanup keep reversing each other: removed over a peer-line mismatch and decided deleted by the user (10-02, maintained 10-03 and 10-04), yet `/etc/nixos`'s `programs.dsh.plugins` still declares it and that HM module ensures missing plugins into `~/.dsh/profiles/web` on every switch while never deleting — so the 10-03 rc.2 switch installed it back, not because its peer was satisfied. Attribute by mtime rather than by version line, and do not require alignment with `home-manager generations`: the 2026-10-04 11:09:38 activation created no new generation and still restored it after a local cleanup took it to deps 15 / bundles 16 / lock 0.
- Profile-layer `cordis.patch.yml` mtime moving forward means the platform is persisting settings, not that someone edited config: the desktop settings pages land changes through `settings.mutate` (upstream `@deepseek-ai/dsh-client-ui-settings-models` documents the file as owned by `cordis.patch.yml`, each write carrying a `revision`, with external concurrent edits rejected as `settings/conflict`). Manual agent edits leave `.bak-<date>-<purpose>` files while the programmatic write left none, and mtime moves even without new content.
- `test/card-render.test.mjs` must supply `react-dom` / `clsx` / `zustand` / `immer` itself because `dsh-client-store` and `dsh-client-ui-primitives` import them while declaring only a cordis peer, and `ui-primitives`' mega-index also imports shiki/katex/micromark/simple-icons, injected as passthroughs. "The server runs the migrated card" means one platform require in `lib/client.js` and none in the deleted hand-written card. A frame's file size is not a page classifier.
- The `本会话 ¥…` line is third-party `dsh-cost-meter`'s cell in the session-scoped `conversation.composer.dock` slot — one per mounted conversation, so different numbers mean different sessions, and it is not this repo's render. Read-only cross-check: client `Slots` on that slot root, host `Config` for `name=dsh-cost-meter`, ledger `~/.dsh/storages/cost-meter/ledger.json` → `days.<date>.sessions[]`. Two lines under ONE composer mean a stale client registration (Ctrl+Shift+R); two composers each with a live line mean two sessions. Turn it off in 设置 → 费用 → 显示设置 → 会话费用显示位置. Known non-defects: the ledger bills per call, and `includeSubagentCost` merges only continuous subagent descendants.
- A verification script must prove its own tool surface and every failure path must be reachable: under `set -euo pipefail`, `x="$(grep … | head -1 | sed …)"` makes the script exit before its own fail branch when the grep misses — for every `var="$(…)"` ask whether the next branch that reads it is still reachable.
- Never rewrite a long line with a prefix-relative replace: the remainder survives and the line ends in a duplicated remnant. Read the line back and check that the same sentence does not appear twice.
