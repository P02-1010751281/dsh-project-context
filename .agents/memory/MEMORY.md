## Memory cap and the loaded-memory trap
- `MAX_MEMORY_CHARS` 32000 (was 24000), `MIN_MEMORY_CHARS` 4000, limit 200000, configurable via `maxMemoryChars`. All `normalizeMemoryDocument` call sites take the limit（`src/` 现为 **6** 处——旧的「9」是过期数，现查 `git grep -n 'normalizeMemoryDocument(' -- src/ | grep -v 'export function' | wc -l`）。
- A capped document is cut on a line boundary (`clipToLineBoundary`, never a bare slice) and gets a marker `_[memory truncated at <limit> characters: <dropped> dropped]_`. Since the 2026-09-25 split: `isMemoryTruncated(text: string)` and `clipToLineBoundary` live in `src/project-memory/document.ts` (**takes the document string, not the `LoadedMemory` object**); `loadMemory(projectRoot, limit)` is **async** and returns `{text, source, poisoned, unreadable?, damaged?}` from `src/project-memory/load.ts`.
- 这个机制修的是**新增内容被静默永久丢弃**：新行落在切点之后，写入时被丢掉（journal append 与 render write 都过 `normalizeMemoryDocument`）。
- Trap：`loadMemory` 返回的文档**已经带 marker**，而 status 对象仍报 `damaged: 0` / `poisoned: false`——`/memory status` 会显示一份健康文档，实际三分之一内容已丢（**marker 的 `dropped` = 归一化后长度 − 保留前缀长度，不等于「原长度 − 保留长度」**——归一化会先剥掉 `# Project Memory` 头、代码围栏与旧 marker 并 trim；**别拿两个数相减去「验算」，也别引用具体值**）。cap 状态自那次修复起才被报告。

## Threshold design — dsh vs pi
- pi's `kneeTokens` 是拟合 MRCR 8-needle 总体数据的跨模型质量曲线：`round(W − (W − 157K) / (1 + e^(−ln(W/450K)/0.04)))`，K = 157K（渐近线，46 个 ≥1M 模型的 p50），Wc = 450K，s = 0.04。目的是**不信声明窗口**（若干声明 1M 的模型实测家族 knee 只有 130–195K）。W ≲ 400K 时 `knee(W)` 已超过 `usable − SAFETY_MARGIN`，所以那里是容量而非曲线在约束。
- **dsh 的 knee 移植曾被写成 `min(configured, knee)`（把显式目标压低的「上限」，正好相反），后经修正并回退那版**。用户的框架「上游优先 + knee 回退保底」是**回退链**、不是上限：`quality = upstreamUsableInput ?? knee(window)`，然后按 pi 的顺序 `threshold = min(max(baseline+keep+summarizeTokens, quality), usable − SAFETY_MARGIN)`（字段名是 pi 的 `summarizeTokens`，不是 `summarizeAmount`）。quality 是基底，配置的目标**抬高**它（所以 `handoffTargetTokens` 仍有意义），容量最后说话。
- **This is a behaviour change, not a no-op**: default `handoffTargetTokens` 64000 / baseline 6000 / keep 20000 now yields pi's documented `boundary` shares（84% @128K / 90% @200K / 95% @400K / 16% @1M / 8% @2M；65K 是 69.5%——**别把百分比与窗口错位配对**，现算 `threshold / W`）；旧的 90K 是 `baseline + keep + target`、根本没有质量层。`W=40000 / keep=0` 那条曾按「拒绝」钉住的用例，在 2026-10-02 的基准修复后**解析为 19616**（原 floor 里含合成信封）；误归因修复的其余断言存活。
- **dsh exposes NO upstream usable-input field** (`LlmResolvedModelInfo.context` is only `{ contextWindow: number }`; no `auto_compact_token_limit` / `usableInputTokens` / `maxInputTokens` anywhere in dsh). `qualityLimit(window, upstream?)` is the seam for the harness change that splits declared capacity from usable input — pass nothing until then; do not fake the first branch. `discovery.ts` (`capacity()` first-match-wins over five spellings) is dsh **core**, not this repo.
- **`resolveThreshold` was split** into `handoffRoom` (feasibility only), `qualityLimit` (the chain), `capacityLimit` (the bound) + an orchestrator that only selects a mode and composes them（原先还列过一个 `summarizeAmount`，该符号已从 `src/` 删除）。It used to mix six jobs, which is why the refusal text and the formula each re-derived the same terms and could drift; `thresholdRefusal` now reuses `handoffRoom`. The user asked for this twice.
- **auto 模式曾「结构上无阈值」，根因是跨计量基准相减（2026-10-02 已修）**：`floor` 原为 `max(0, totalTokens − surfaceTokens) + keep + MIN_SUMMARIZE`。dsh 的 meter 里 `totalTokens` 锚在 provider `usage`、`surfaceTokens` 是固定密度启发式（`estimate.ts` 的 `CHARS_PER_TOKEN = 4`），两个基准不同 ⇒ 差值是**真开销 + 密度误差**。真机 `W=1M`：`495117 − 231793 = 263324`，而同一次请求里 dsh 自己定义的信封只有工具 schema 的 `42845`（`estimateToolsTokens` 注释：system prompt 是 surface 节点、信封只此一个计价字段）⇒ **22 万全是误差**，且随中文字符数**线性增长** ⇒ `floor` 永远 > `knee(1M)=157000` ⇒ `resolveThreshold` 恒 `undefined`、自动路径在 `auto.ts:42` 静默退出，回执还把原因说成 `quality-knee`（杠杆指错）。**修法**：`floor` 不再合成信封，改读可选的 `ContextMeasurement.overheadTokens`，信封**不是猜的**：`ctx.sessionProjections.snapshot(session, ['contextBreakdown'])`（token-meter 注册的 projection，`systemTokens + toolsTokens`＝信封；GUI 上下文面板读同一个）现查在世。`quality-knee` **仍然可达**，但只剩用户自己那一条路：`handoffKeepTokens` 上界 200000（`config.ts`），1M 窗口下现查 `keep=149000` 解析、`149001` 拒绝（`/handoff keep 200k` 的真实命令解析器也接受）；harness 报出的信封同样能触及它（本机现查 `contextBreakdown` 的 `toolsTokens` 约 4 万量级，够不到 149001 那条线）。回执按「`keep` 能否清掉膝」分别给词——不能清时**不再**把 `keep` 说成杠杆（旧 “a smaller baseline” 的同一种病）。**「值不值得折」由 `auto.ts:61` 对真实 `handoffSplit` 比 `MIN_SUMMARIZE` 独占**——threshold 层那份是同一规则的第二份、且基准混用的副本。**别再把这条读成「knee 是硬顶所以永不触发」**，那是把计量口径的产物当成了模型行为。杠杆仍成立：`/handoff now` 两个闸都不查；`/handoff 0.4` 不过膝。**诊断别倒序**：两个守卫（pending question / 跑着的子代理）都排在阈值之后。**另一个独立拦截点**：`handoffPendingQuestion: "defer"` 会在「最后一条是问句」时延后——agent 每轮以问句收尾时 auto 每次都被挡下（2026-10-02 本机两次 `turn/end` 实测 `textAsksQuestion` 皆 true）；要它不挡就 `/handoff pending wait`。

## Conventions
- NEVER hand off, compact, or end a turn while a teammate is running——在飞的 teammate 随父回合一起死、工作丢失。它们是进程内的（`~/.dsh/sessions/` 没有条目），只显示 `provisioning → active`、没有终态，所以死掉的 teammate 不留失败事件。规则：`list_agents` + 等每个在跑的 teammate（或显式 interrupt）之后才能交接/压缩；对 inactive 成员 `send_message` 不可信；用重查 `list_agents`/`team_task_list` 确认，别信 send 的 accepted 状态；从 `/tmp` 抢救半成品而非盲目重开；要求每个 teammate 边做边把报告写到固定路径。
- A teammate that dies mid-mutation leaves `src/` dirty: snapshot `src/` (copy + `sha256sum`) into the task text before spawning, require the restore command in the report, and run `sha256sum -c` after every teammate settles or dies; treat an unrestored mutation as unverified work.
- An unvalidated mutant produces an invalid red. A valid mutant must (a) compile with 0 errors, (b) have its marker in `lib/` **after** `pnpm build`, (c) demonstrably change behaviour on a probe input. Restoring `src/` does NOT restore `lib/` — end a mutation round with a rebuild and marker count 0. Edit `src/` (editing `lib/*.js` is overwritten and yields a false SURVIVED), restore from a hash-verified `/tmp` copy, never via `git checkout --` or `git stash`, and scope the run at least to the file that owns the pinning test.
- A heuristic wording classifier does not converge by patching — it trades one error class for another. When two rounds swap the same bug back and forth, you are missing a discriminator, not a pattern.
- **验证脚本必须自证工具面，且每条失败路径都要真的能到达**：`set -euo pipefail` 下 `x="$(grep … | head -1 | sed …)"` 的 grep 无命中会让脚本**在它自己的 fail 分支之前**退出，那个 fail 对它要报的场景永远不可达；`REPO="$(cd … && pwd)"` 同理。检出办法：对每条 `var="$(…)"` 问「它失败时，下一个读它的分支还到得了吗」。两种假绿的具体案例在 `/etc/nixos/scripts/dsh-plugin-patches/PINNING-RISK.md`。
- **改长行不要用「按前缀 replace」的脚本**：本轮它只换了半句，把 `CONTEXT.md` 的那一行拼出一段重复残尾。改写后要读回该行，并检查「同一句出现两次」，别只看替换是否「成功」。
- Memory stays concise (< 6000 words); no secrets, credentials, or generic advice; unresolved work lives in memory/context, not in skills.
- Do not touch the user's own dsh sessions; goal/session control belongs to the user's agent session. Read-only investigation of `~/.dsh` stores is fine (`zstdcat session.v3.jsonl.zstd`); throwaway probe sessions only under `/tmp`, archived afterwards.

- Do not restart the user's `dsh web` service unprompted; propose the restart.
