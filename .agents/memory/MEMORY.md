## Memory cap and the loaded-memory trap
- `MAX_MEMORY_CHARS` 32000 (was 24000), `MIN_MEMORY_CHARS` 4000, limit 200000, configurable via `maxMemoryChars`. All `normalizeMemoryDocument` call sites take the limit（`src/` 现为 **6** 处——旧的「9」是过期数，现查 `git grep -n 'normalizeMemoryDocument(' -- src/ | grep -v 'export function' | wc -l`）。
- A capped document is cut on a line boundary (`clipToLineBoundary`, never a bare slice) and gets a marker `_[memory truncated at <limit> characters: <dropped> dropped]_`. Since the 2026-09-25 split: `isMemoryTruncated(text: string)` and `clipToLineBoundary` live in `src/project-memory/document.ts` (**takes the document string, not the `LoadedMemory` object**); `loadMemory(projectRoot, limit)` is **async** and returns `{text, source, poisoned, unreadable?, damaged?}` from `src/project-memory/load.ts`.
- 这个机制修的是**新增内容被静默永久丢弃**：新行落在切点之后，写入时被丢掉（journal append 与 render write 都过 `normalizeMemoryDocument`）。

## Threshold design — dsh vs pi
- pi's `kneeTokens` 是拟合 MRCR 8-needle 总体数据的跨模型质量曲线：`round(W − (W − 157K) / (1 + e^(−ln(W/450K)/0.04)))`，K = 157K（渐近线，46 个 ≥1M 模型的 p50；p25 127K / p75 190K），Wc = 450K，s = 0.04。目的是**不信声明窗口**（grok-4.5/4.6 声明 500K、实测家族 knee ~195K；若干 1M 声明模型实测 knee 130–170K）。W ≲ 400K 时 `knee(W)` 已超过 `usable − SAFETY_MARGIN`，所以那里是容量而非曲线在约束。
- **dsh 的 knee 移植在 `a7b1c1d` 修正**（`8557fb1` 已被 `011a68e` 回退）。用户的框架「上游优先 + knee 回退保底」是**回退链**、不是上限：`quality = upstreamUsableInput ?? knee(window)`，然后按 pi 的顺序 `threshold = min(max(baseline+keep+summarizeTokens, quality), usable − SAFETY_MARGIN)`（字段名是 pi 的 `summarizeTokens`，不是 `summarizeAmount`）。quality 是基底，配置的目标**抬高**它（所以 `handoffTargetTokens` 仍有意义），容量最后说话。**`8557fb1` 写成 `min(configured, knee)`——把显式目标压低的「上限」，正好相反，且让「上游字段缺失」等于曲线失效。**
