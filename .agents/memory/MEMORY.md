## Pitfalls
- Memory loss in a consolidation pass happens before or at the write, so a document that re-renders clean proves nothing; the five sites are `fitMemoryInput` head-and-tail clipping, `renderMemoryDocument` dropping whole entries over a section budget, the stored context sliced to `MAX_CONTEXT_CHARS` before the fit, `renderContextDocument` clipping its own sections, and `normalizeMemoryDocument` capping on write; `ConsolidateReport` carries the six loss counts plus `memoryWritten`/`contextWritten`, zeroed unless that artifact landed.
- `/memory update` can refuse for two unrelated reasons — the section budgets (`lossy-refused`, reported as `N section(s) exceeded their budget` or `N whole entry(ies) … because the memory document reached its character cap`) and the model output cap (`cut off by the model output limit`); raising `maxMemoryChars` only aggravates the output half, the durable fix is shrinking the document, and a third wording `fit-capped-refused` means the output budget cannot hold both documents.
- Gate numbers and occupancy prose both expire: run `pnpm typecheck` / `pnpm build` / `pnpm test` and read fresh pass/case counts, take `lib/client.js` size from the build output, expect 0 mutant markers, and re-measure per-section occupancy through the built renderer (`share-fit.mjs`) instead of trusting written percentages — tier C's whole-entry refusal is one small growth away.
- `share-fit.mjs` measures against the library default `MAX_MEMORY_CHARS`, not the profile's `maxMemoryChars`, so it can report a lossy verdict the running host would never produce; compare against the configured cap before believing it.
- The loaded-memory trap: `loadMemory` can return a document that already carries the truncation marker while the status object still reports `damaged: 0` and `poisoned: false`; the marker's `dropped` is normalized length minus kept prefix length, not original minus kept — never verify it by arithmetic and never grep for the marker.
- `tsc` emits tagged templates as `String.raw` followed by the template with a space, so `grep -cF` for an in-template marker returns 0 and looks like a failed restore or an empty mutant; locate mutants with `grep -n "<NAME> = "` in `lib/`.
- String counts taken from session logs are unusable because logs echo the agent's own command output, so `grep -c` mostly counts the probe itself; judge live behaviour through read-only interfaces (`cordis_inspect_query` `Config`/`Service`, projection caches).
- Do not filter a multi-line log by string-comparing whole lines against a timestamp: continuation lines of a stack trace start with `{` or whitespace and sort after `2026…`, so they read as newer entries and hide the one real error — match a line-leading timestamp instead.
- A restart-time `[handoff] LlmError: … has no configured model …` is a stale provider/model pair read from the session request header during a mid-session model switch, not a code defect: `resolveTarget` falls back to the header and `gate.ts`'s `resolveModelInfo` throws unguarded into `index.ts`'s catch, which logs and sets a 5-minute backoff; prove healing by reading the live session's latest request headers, and treat a route pinned to a dead model as a design question for the user, not a bug.
- `[memory] … cannot get required service "llm" in inactive context` lines a second or two before a host start are the old instance's dispose-time cleanup, not a new defect (cluster at every shutdown); likewise a cap-loss line dated just before a restart was written by the old code under the old cap.
- `/handoff status` receipts do not self-identify: `threshold auto` and `context` are profile- and model-level numbers identical across workspaces, so any citation must carry workspace plus session id.
- An invalid mutant's red is not evidence — leaving a symbol unreferenced in `src/` makes `tsc` report `TS6133`, so keep every symbol referenced before judging red.
- Cross-repo transfer trap: dsh's finish reason is `max-tokens` while pi's is `length`, and copying pi's string silently disables the retry path.
- pi batch I (loaded): the injected documents keep the policy sections inline and index the rest; an unnamed heading and a trailing `_[…]_` note stay inline, pointers are absolute, and the pointer language follows the document's own detector (`src/shared/language.ts`).
- pi batch J (loaded): the handoff summarizer is gone and `handoffThinking`/`/handoff thinking` retired hard-cut, so `/handoff now` needs no routed model while the auto path still resolves `contextWindow`; `isHandoffContinuationText` stays structural — a payload change must keep all six `<handoff>` closings matching or a seed counts as a human turn.
- The harness's subagent-list `activity` field means resident, not working: `list-children.ts` builds `childRow(…, 'running', …)` for every candidate `sessions.get(id)` still holds and only a cold read gives `inactive`, so judge live work with upstream's `list_agents`; `subagents.listChildren(parentId)` reads the parent-owned `subagent/catalog` projection instead.
