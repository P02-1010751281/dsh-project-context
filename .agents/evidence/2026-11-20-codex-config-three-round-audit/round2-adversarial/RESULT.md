# Adversarial finding: a parsing fix, not a feature backport

Keep the boolean spelling. It removes a reproducible thread-start blocker and retains the newer CLI's opt-in. **Do not claim it enables async compaction on the plugin's 0.153.4:** that executable explicitly rejects the named flag. A router 200 cannot resolve this question.

## Controls and results

Ran [probe.py](probe.py) with `python3 probe.py <absolute path to the supplied 0.153.4 codex.js>`. [Observed outputs](observations.txt). New processes, temporary HOME/CODEX_HOME/XDG/TMPDIR under this directory; no plugin invocation or live config changes. Handshakes used fresh processes and the same temporary config path, not cached threads. ## Remaining ways to be wrong, ranked

1. **Feature preservation on the bundled runtime** — strongest: its own registry rejects the name. To demonstrate otherwise, trigger compaction on identical old-client long sessions against a controlled provider, alternating only true/false, and show a repeatable *async-specific* event or request-order difference. Ordinary compaction or a successful short turn does not count.
2. **Attributing a historical failure to the reproduced bug** — reproducibility establishes sufficiency, not which bytes the historical child read. Recover the child-linked original startup diagnostic with binary/config identity. If no trace survives, a matched plugin replay with the original backup vs. the final file on a fixed mock route can settle the counterfactual, not the historical bytes. No plugin replay was run this round.
3. **Treating any successful handshake as end-to-end validity** — the unknown-model handshake already disproves that generalization. For another cwd/model, vary one factor at a time and capture thread reply, turn result and provider request ID together. For exact router-row attribution, join on the Codex thread/session ID rather than time proximity alone.

The strongest alternative explanation is therefore narrow: billing or routing recovered while a parseable configuration was already in place; the old runtime needed the map gone, not a working async-compaction switch. This explains the later success without explaining away the original type error.
