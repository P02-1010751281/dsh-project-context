# 校准：missing literals 在真实 journal 历史上的取值（2026-11-21）

对应规格 `docs/memory-rewrite-loss-gate-spec.md` §3 A / §9。这份校准回答两件事：这个指标在这
个仓库自己的历史上**是 0 还是常态**，以及它的量级是否与「一次 pass 静默概括几条事实」相符。

## 复现

```bash
node .agents/evidence/2026-11-21-missing-literals-calibration/calibrate.mjs
```

脚本只读 `.agents/memory/memory*.jsonl`（6 份：5 份 rotate 出来的归档 + 当前 1 份），按
`op: "replace"` 取出每次落盘的整篇文档，用**已落地的** `lib/project-memory/missing-literals.js`
逐对比较，输出 `output.txt` 里的表。

## 结果（`output.txt`）

| 指标 | 值 |
|---|---|
| journal | 6 |
| 转换（相邻两次落盘文档） | 66 |
| 零丢失 | 30（45%） |
| 平均丢失字面量 | 5.41 / 次 |
| 中位数 | 1 |
| 最大 | 67 |
| p90 | 13 |

结论：**不是极端案例**。接近一半的转换一条不带；但另一半每条丢几个，长尾到 67。这与 tier C 的
三个结构计数在这些转换上常年为 0 是同一件事的两面——整篇重写的概括不改变结构，只带走字面量。

## 与旧数字的差别（必须记住）

上一轮（2026-11-20）报的那组 **59 次转换、平均 6.41、最大 68**，在这里复现出来了——它等于
「5 份归档 + 先配对、但不做裸文本检查」这一版（59 次、零丢失 26、均值 6.41、最大 68）。也就是说那组
数字的问题是**缺了裸文本那一层**，不是反引号配错。两条规则各自的代价都能单独量出来（5 份归档、
59 次转换）：

| 抽取规则 | 均值 | 最大 | 零丢失 | 总数 |
|---|---|---|---|---|
| 先配对、无裸文本检查（上一轮的口径） | 6.41 | 68 | 26 | 378 |
| 先配对 + 子串裸文本检查（本批第一版） | 5.14 | 57 | 27 | 303 |
| 先配对 + 整词裸文本检查（落地版） | **5.85** | **67** | 27 | **345** |

而 §8 那行「在匹配阶段就过滤短 span」的正则，在同一批 59 次转换上是 **7.46 / 74 / 23**：它凭错配
多报，与上面任何一版都不同。mispairing 自身的代价有独立证据，是 §1 那对文档的 61 vs 57。

本文正文上表的数字是 **6 份 journal / 66 次转换**（含当前 `memory.jsonl`）的口径；上面这张比较表是
**5 份归档 / 59 次**（上一轮口径的样本）。两套样本不要混用，**引用数字时用正文这一份**。

子串规则在 66 次那套上的代价也单独量过：

| 裸文本判定 | 总丢失 | 均值 |
|---|---|---|
| `next.includes(literal)`（第一版，子串即算还在） | 313 | 4.74 |
| 整词 + 反引号之外（落地版） | 357 | 5.41 |

即子串规则**掩盖了 44 条真实丢失**（占落地版总数的 12%），方向正好是「让这个指标看不见它要看的
东西」，所以它被独立评审列为缺陷而不是保守选择。
